# 04. 기능 명세

[03 요구사항](03-requirements.md)을 실제 동작 규칙으로 옮긴다. 괄호 안의 ID(예: B-1)는 요구사항 번호다. 화면 배치는 5단계(와이어프레임)에서, 구현 방법은 7단계(기술 설계)에서 정한다.

**이 문서에 적는 것**: 되돌릴 수 없는 동작(삭제, 탈퇴), 보안, 개인정보, 비용이 드는 동작, 숫자로 된 규칙. **적지 않는 것**: 로딩 표시, 중복 클릭 방지, 에러 문구, 빈 화면 안내, 입력 형식 검사 같은 일반적인 화면 동작. 이런 것은 와이어프레임과 개발 단계에서 흔히 쓰는 방식대로 넣는다.

## 이번에 확정한 것

| 항목 | 결정 | 이유 |
|---|---|---|
| 로그인 | **GitHub, Google, 카카오** 소셜 로그인 | 개발자는 GitHub, 비전공자는 Google, 한국 사용자는 카카오가 가장 편하다. 셋 다 무료다. 메일 기능이 없어 이메일을 받지 않아도 되므로 카카오도 별도 심사 없이 쓸 수 있다 |
| 알림 시각 | 사용자가 1시간 단위로 고른다. **기본 오전 8시** | 출근길, 점심, 퇴근 후처럼 연습하는 시간이 사람마다 다르다 |
| 놓친 날 | 다음 날은 **새 질문만** 주고, **일주일에 한 번은 꼬리잇기를 지켜준다** | 밀린 숙제가 쌓이면 부담돼서 아예 안 들어오게 된다. 한 번 빠졌다고 긴 꼬리잇기가 0이 되면 의욕이 꺾인다 |

## 1. 계정 (A-1, A-4)

- 소셜 로그인 3종. 처음 로그인하면 가입이 되고 온보딩으로 간다.
- 로그인 방법이 달라도 이메일이 같으면 한 계정으로 이어지고, 이메일이 다르면 새 계정이 만들어진다. 로그인 화면에 "이메일이 같으면 한 계정으로 이어지고, 다르면 새 계정이 만들어져요."라고 안내한다.
- 탈퇴하면 계정과 모든 기록(답변, 채점, 프로젝트, 알림 구독)을 **바로** 지운다. 되돌릴 수 없으므로 아래 순서를 모두 거친다.
  1. 지워지는 데이터 목록을 보여준다
  2. "탈퇴합니다"를 그대로 입력해야 탈퇴 버튼이 켜진다 (실수 방지). 입력칸에 따라 쓸 문구 "탈퇴합니다"를 흐리게 보여준다
  3. 마지막 로그인이 24시간보다 오래됐으면 **같은 소셜 로그인으로 다시 확인**한다. 소셜 로그인이라 비밀번호가 없으므로, 이것이 비밀번호 확인 역할을 한다 (열린 화면에서 다른 사람이 탈퇴시키는 것 방지). 검사는 서버(`DELETE /api/me`)가 하고, 화면은 서버가 다시 확인을 요구했을 때만 오류 문구와 "OO 로그인으로 확인하기" 버튼으로 알린다. 처음엔 입력칸 아래에 "로그인한 지 24시간이 지났으면 소셜 로그인으로 한 번 더 확인해요"를 늘 적었으나, 대부분은 해당하지 않는 말이라 뺐다 (2026-10-27, #118)
  4. 즉시 삭제하고 로그아웃한 뒤 랜딩 페이지로 보낸다

### 프로필 (A-7)

- **닉네임**: 처음엔 소셜 계정 이름으로 시작하고 설정에서 바꾼다. 2~12자. 다른 사람과 겹쳐도 된다(서로 볼 일이 없으므로).
- **프로필 이미지**: 처음엔 소셜 계정 사진을 쓰고, 원하면 기본 아바타 몇 개 중에서 고른다. **사진 업로드는 받지 않는다.** 저장 공간과 부적절한 사진 검수 부담이 없다.
- 닉네임은 내 화면과 공유 카드에 보인다. 공유 카드에서는 뺄 수 있다. 프로필 이미지는 공유 카드에 넣지 않는다.

## 2. 온보딩 (A-2, 개인정보)

첫 로그인 직후 한 번 거친다. 두 단계다.

1. **동의**: 이용약관, 개인정보처리방침(국외 이전 포함), 만 14세 이상 확인. 셋 다 필수다.
2. **연습 범위**: 분야·세부 주제·난이도를 여러 개 고른다. 최소 1개 주제는 골라야 한다. 범위를 저장하면 온보딩이 끝난다.

- **알림은 온보딩에서 묻지 않는다.** 첫 오늘의 질문을 끝낸 홈에서 알림이 꺼져 있으면 알림 받기와 시각을 한 번 묻는다("나중에"를 누르면 이 기기에서는 다시 묻지 않는다). MY에서 언제든 켤 수 있다. 처음엔 3단계로 알림 허용과 시각을 받았으나, 2026-10-28 디자인 리셋에서 빼고 홈으로 옮겼다.

### 연습 범위 선택지

| 분야 | 세부 주제 |
|---|---|
| 공통 CS | 자료구조·알고리즘, 네트워크, 운영체제, 데이터베이스 |
| 백엔드 | Java, Spring, JPA, 트랜잭션·동시성, 인증·보안, 설계·아키텍처 |
| 프론트엔드 | JavaScript, TypeScript, React, 브라우저·렌더링, 웹 성능 |

난이도는 **기본 / 중급 / 심화** 3단계다. 분야를 고르면 그 아래 세부 주제가 모두 선택되고, 하나씩 뺄 수 있다.

## 3. 오늘의 질문 (B-1, B-3, B-5, B-6)

- **하루의 경계는 한국 시간 자정**이다. 하루 동안 오늘의 질문은 바뀌지 않는다.
- 오늘의 질문을 고르는 순서:
  1. 오늘이 복습일인 질문이 있으면 그중 **가장 오래 밀린 것**
  2. 없으면 연습 범위 안에서 **아직 안 푼 새 질문**. 최근 며칠 동안 나온 주제는 피해서 주제가 고르게 돌게 한다
  3. 새 질문도 없으면(범위 소진) 가장 가까운 복습 예정 질문을 **앞당겨** 내고, "범위 안의 새 질문을 다 풀었어요. 범위를 넓혀볼까요?"를 안내한다
- 앞당길 복습 질문도 없으면(범위가 비었거나 모두 복습 완료) 홈은 "범위 안의 새 질문을 모두 풀었어요. 연습 범위를 넓혀 볼까요?"와 "연습 범위 넓히기" 버튼(연습 범위 화면 `/my/range`로 간다)을 보여준다.
- **놓친 날**: 그날의 새 질문은 사라진다. 복습 질문은 사라지지 않고 다음에 들어왔을 때 다시 나온다.

## 4. 답변·채점·꼬리질문 세션 (C-1~C-6)

오늘의 질문 하나를 **본 질문 + 꼬리질문**으로 묶어 "세션"이라고 부른다.

| 단계 | 동작 |
|---|---|
| 답변 | 텍스트로 쓴다. **30자 미만이거나 2,000자 초과**면 제출 전에 알려준다 |
| 채점 | 점수, 잘한 점, 빠진 점, 모범 답안을 보여준다. 결과는 생성되는 대로 흘러나오듯 보여준다. **모범 답안은 제출한 뒤에만** 보인다 |
| 꼬리질문 | 앞선 답변을 바탕으로 만든다. **최소 2개, 최대 3개.** 답이 충분히 깊으면 2개에서 끝난다. 꼬리질문 답변도 짧게 채점한다 |
| 종합 | 세션이 끝나면 종합 결과를 보여준다: 본 질문 점수, 꼬리질문별 결과, 다음 복습일 |
| 참고 자료 | 모범 답안 아래에 공식 문서(MDN, Spring 문서, React 문서 등) 링크를 1~3개 보여준다 |
| 북마크 | 세션 중이나 기록에서 질문을 별표로 북마크한다 |
| 평가 | 채점 결과마다 👍/👎를 남길 수 있다 |
| 모르겠어요 (C-7) | 답 대신 "모르겠어요"를 누를 수 있다. AI 채점 없이 모범 답안과 참고 자료를 바로 보여주고, 0점으로 기록해 복습 1칸에 넣는다. 꼬리질문에서 누르면 그 꼬리질문의 기대 답안을 보여주고 세션을 종합으로 넘긴다. 꼬리질문의 기대 답안은 꼬리질문을 만들 때 같이 만들어 두므로 AI를 다시 부르지 않는다. 답을 쓴 채 누르면 쓴 답이 지워지므로 "쓴 답을 지우고 넘어갈까요?"를 먼저 묻는다([계속 쓰기] [넘어가기]) |
| 신고 | 채점 결과(본 질문·꼬리질문)와 질문 상세 아래에 "질문이나 채점에 문제가 있나요?" 링크를 둔다. 누르면 피드백 화면이 분류 "신고"와 질문 번호(본문 첫 줄 "Q.042 질문 신고: ")를 미리 채운 채 열린다. 꼬리질문에서도 본 질문 번호로 보낸다. 체험에는 없다 (#134) |

- **학습한 날**: 본 질문에서 "모르겠어요"를 눌러도 모범 답안을 읽었으므로 학습한 날로 친다. 매일 들어오는 습관이 우선이다.
- **이어하기**: 세션 진행 상황은 단계마다 저장된다. 나갔다 들어오면 멈춘 곳부터 이어간다.
- **쓰던 답변**: 제출 전 답변은 글자를 칠 때마다 이 기기에 남기고, 다시 들어오면 되살린다(서버에 저장된 답변이 있으면 그쪽이 먼저). 제출하면 지운다. 처음엔 나가기 창으로 나갈 때만 남겨서 새로고침·탭 닫기·모바일 백그라운드 종료에 사라졌다.
- **날짜를 넘긴 세션**: 본 질문을 그날 안에 제출하지 않았으면 그 세션은 끝나고, 다음 날은 새로 고른 질문이 나온다(놓친 날의 새 질문은 사라진다는 규칙과 같다). 복습 질문이었다면 복습 일정은 그대로 남는다. 본 질문을 제출했으면 학습한 날과 복습 일정은 그날 반영되고, 남은 꼬리질문은 **다음 날 오늘의 질문을 시작할 때 "건너뜀"으로 기록되며 세션이 끝난다.** 홈은 항상 세션 하나만 보여준다. 처음엔 "날짜가 바뀌어도 이어갈 수 있다"고만 적었으나 놓친 날 규칙과 부딪혀서 나눴고(2026-10-23), 그 뒤 "본 질문을 제출했으면 꼬리질문은 다음 날 이어갈 수 있다"로 두었으나 열린 세션이 둘(어제 꼬리질문 + 오늘 새 질문)이 되어 홈이 어느 것을 보여줄지 정해지지 않아 지금처럼 바꿨다 (2026-10-25, [08 설계](08-architecture.md)).
- **복습 칸은 본 질문 채점 때 정해진다.** 꼬리질문을 끝내지 않아도 복습 일정은 반영된다.
- **실패 처리**: 채점이 실패하거나 15초를 넘기면 "다시 채점하기"를 보여준다. 쓴 답변은 지워지지 않는다.
- 점수 체계(100점제 또는 등급)는 7단계 #10에서 정한다.

## 5. 복습 (D-1, D-2)

5칸짜리 상자로 간격을 정한다. 잘 답하면 다음 칸으로, 부족하면 1칸으로 돌아간다.

| 칸 | 다음 복습까지 |
|---|---|
| 1 | 1일 |
| 2 | 3일 |
| 3 | 7일 |
| 4 | 14일 |
| 5 | 30일 |

- 처음 푼 새 질문은 잘 답하면 2칸(3일 뒤)에, 부족하면 1칸(1일 뒤)에 넣는다. 처음엔 시작 칸이 정해져 있지 않았다. 잘 답한 질문도 한 번은 다시 확인하려고 2칸으로 정했다 (2026-10-25).
- 5칸에서도 잘 답하면 "복습 완료"한 질문이 되어 복습에서 빠진다. 처음엔 "익힌 질문"이라 불렀으나 복습 화면의 필터·안내와 같은 말로 맞추려고 "복습 완료"로 바꿨다 (2026-10-27).
- "잘 답함"과 "부족함"을 가르는 점수 기준은 #10에서 정한다.
- 복습 예정 질문과 날짜는 "내 질문" 화면(6번)에서 본다. 처음엔 복습 목록 화면(제목 "복습", 그 아래 "복습 예정 항목 N개")이 따로 있었으나, 2026-10-28 디자인 리셋에서 기록 목록과 합쳤다.
- 홈의 "복습할 질문"은 복습 예정 질문을 복습일이 가까운 순(밀린 것 먼저)으로 3개까지 보여준다. 오늘의 질문은 위에 크게 있으므로 뺀다. 줄마다 복습 시기, 질문, **가장 최근 본 질문 점수**("모르겠어요"였으면 "–"), 숙련도를 둔다. 누르면 질문 상세로 간다.
- **사용자에게는 칸 번호를 보여주지 않는다.** "3일 뒤 다시 · 숙련도 ●●○○○"처럼 다음 복습일과 숙련도 막대(5칸)로 보여준다. "칸"은 사용자가 뜻을 알기 어렵다는 이유로 바꿨다 (2026-10-22).

## 6. 기록과 동기부여 (E-1~E-3)

- **내 질문** (`/questions`): 복습 목록과 학습 기록을 **질문 하나에 한 줄**로 합친 목록이다. 줄마다 복습 시기(복습 완료 포함), 질문, 번호·주제·푼 횟수, 가장 최근 본 질문 점수("모르겠어요"는 "–"), 숙련도를 둔다. 필터 칩은 오늘 복습 · 이번 주 · 북마크 · 복습 완료 · 전체이고 칩마다 개수가 붙는다. 기본은 오늘 복습할 질문이 있으면 "오늘 복습", 없으면 "전체"다. "북마크"로 걸러서 면접 직전에 몰아서 볼 수 있다 (E-4). 달별 묶음과 달 건너뛰기는 없다.
- **질문 상세** (`/questions/[id]`): 질문 하나의 복습 상태와 날짜별 기록(날짜, 점수)을 본다. 기록을 누르면 그날의 기록 상세(내 답변, 채점, 꼬리질문, `/history/[id]`)로 간다.
- 처음엔 복습 탭과 기록 탭이 따로 있었고, 기록은 세션 하나에 한 줄로 달마다 나눠 이어 붙인 피드(달 머리 옆 화살표로 달 건너뛰기)였다 (2026-10-27). 2026-10-28 디자인 리셋에서 "내 질문" 하나로 합치고 날짜별 기록은 질문 상세에서 보게 했다.
- **학습한 날**: 그날 본 질문 답변을 제출하면 학습한 날이다.
- **꼬리잇기**: 연속으로 학습한 날 수. "꼬리잇기 12일째"로 보여주고(앱 머리 막대는 글자만, 리포트 제목 앞에만 작은 꼬리 아이콘을 둔다. 와이어프레임의 🔥는 자리표시였다), 처음 보는 곳에서 "하루도 빠지지 않고 이어서 푼 날 수"라고 한 번 설명한다. 처음엔 "스트릭"이었으나 일반 사용자가 뜻을 모를 것 같아 TailQ와 이어지는 이름으로 바꿨다(2026-10-22). 같은 이유로 "보호권"도 "휴식권"으로 바꿨다. 하루 빠지면 그 주(월~일)의 **휴식권 1개**를 자동으로 써서 이어준다. 휴식권이 없으면 0이 된다. 휴식권은 매주 월요일에 1개로 채워진다.
- **꼬리잇기 달력**: 날짜별 칸. 학습한 날은 점수에 따라 색이 진해진다. 휴식권을 쓴 날은 다른 표시를 한다. 칸에 마우스를 올리면 날짜와 점수(학습하지 않은 날은 "기록 없음")를 보여준다. 1년(52주) 고정이고, 첫 칸은 사용자가 시작한 주(가입일, 가입 전 체험을 이어받았으면 첫 학습일이 든 주의 월요일)다. 시작한 주부터 채워지고 오늘 뒤 칸은 앞으로 채울 칸으로 흐리게 비워 둔다. 시작한 지 1년이 넘으면 이번 주가 마지막 열이 되게 앞으로 민다. 처음엔 "학습 잔디"라는 이름으로 최근 1년만 보여줬으나, 칸이 작고 빽빽해 보인다는 의견으로 이름을 꼬리잇기와 잇고 주·월·3개월·1년 보기 전환(기본 3개월)을 넣었다. 그 뒤 처음부터 채워지는 느낌이 나도록 보기 전환을 빼고 1년 고정, 시작한 주부터 채우게 바꿨다 (2026-10-27).
- **약점 리포트**: 세부 주제별 평균 점수와 주간 추이. 3번 이상 푼 주제만 보여준다(그 전에는 "데이터가 모이는 중").

## 7. 웹 푸시 알림 (B-7, B-8)

- 정해진 시각에 "오늘의 질문이 도착했어요" 알림을 보낸다. 오늘이 복습 질문이면 "복습할 질문이 있어요"로 바꾼다.
- **오늘 이미 풀었으면 보내지 않는다.**
- 알림을 누르면 오늘의 질문 화면이 열린다.
- 아이폰은 홈 화면에 추가해야 알림을 받을 수 있다(iOS 16.4 이상). 아이폰에서 알림을 켜려고 하면 추가 방법을 안내한다.
- 설정에서 언제든 끄거나 시각을 바꾼다.

## 8. 공유 (F-1, F-2)

- 세션 결과 화면에서 공유한다. 카드에는 **닉네임, 질문 주제, 점수, 꼬리잇기**만 넣는다. 질문 원문, 답변, 프로필 이미지는 넣지 않는다. 닉네임은 공유할 때 뺄 수 있다.
- 공유 링크를 열면 공유 페이지가 뜬다: 카드와 "나도 풀어보기"(체험으로 연결).
- 메신저에 링크를 붙이면 카드 이미지가 미리보기로 뜬다.

## 9. 내 프로젝트 기반 질문 (G-1~G-3)

- "내 프로젝트" 메뉴에서 프로젝트 이름과 README·설명을 붙여 넣는다. **최대 10,000자.**
- 질문을 **5개** 만든다. 프로젝트의 설계 이유, 기술 선택, 트러블슈팅을 묻는 질문 위주로.
- 만든 질문은 바로 세션으로 연습한다. 부족했던 질문은 복습 상자에 들어가 오늘의 질문 후보가 된다.
- 프로젝트는 **최대 3개**까지 등록한다. 보고 지울 수 있고, 내용을 바꾸려면 지우고 다시 등록한다.
- 프로젝트 목록의 줄마다 연습 진행을 보여준다: "질문 5개 · 아직 연습 안 함" 또는 "5문제 중 3개 연습 · 평균 68". 본 질문을 채점받은(답했거나 모르겠어요) 질문을 연습한 것으로 세고, 평균은 질문마다 가장 최근 본 질문 점수로 낸다(모르겠어요는 뺀다). 만드는 중·만들지 못함도 같은 자리에 보인다.
- 프로젝트를 지우면 그 프로젝트의 질문과 답변 기록, 복습 일정도 함께 지워진다. 질문 목록 맨 끝의 작은 빨간 글자 링크 "프로젝트 삭제하기"를 누르면 이 내용을 알리는 확인 창이 뜨고, 프로젝트 이름을 똑같이 입력해야 실행 버튼(빨간 바탕 + 흰 글씨 "삭제")이 켜진다 (#118). 처음엔 목록 맨 아래에 빨간 바탕 버튼을 두었으나 2026-10-28 디자인 리셋에서 확인 창으로 들어가는 길은 작은 글자 링크로 바꿨다.
- **오늘의 질문이 그 프로젝트의 질문(복습으로 나온 경우)이면 그날은 지울 수 없다.** "오늘의 질문으로 나온 프로젝트는 내일 지울 수 있어요"를 안내한다. 지우면 오늘 세션과 학습한 날이 함께 사라지기 때문이다 (2026-10-25, [08 설계](08-architecture.md)).
- 붙여 넣은 내용은 질문 생성에만 쓴다.

## 10. 처음 온 사람 (A-5, A-6)

- **랜딩 페이지**: 아래로 스크롤하는 긴 페이지다. **3초 규칙**: 첫 화면만 보고 3초 안에 "AI가 채점하고 되묻는 매일 기술면접 연습"이라는 걸 알 수 있어야 한다. 한 사람의 하루(Q.226 본 질문 74점 → 꼬리질문 3개 → 복습 → 기록)를 **실제 앱 화면 조각**으로 따라간다. 숫자는 통계·후기가 아니라 화면 예시다.
  1. 첫 화면: "하루 한 문제, AI가 채점하고 되묻는 개발자 기술 면접 연습", 한 줄 설명, "로그인 없이 한 문제 풀어보기"(누르면 맨 아래 체험으로 내려간다). 옆에 채점 결과가 도착한 화면 조각(점수, 20칸 막대, 한 줄 평, 보완할 개념)
  2. 15개 주제, 매일 한 문제: 실제 질문 예시가 두 줄로 반대 방향으로 흐르는 띠("흐름 멈추기" 스위치), 아래에 연습 범위 15개 주제 이름
  3. 100점 만점 채점, 잘한 점부터 짚는 피드백: 잘한 점·보완할 점·모범 답안, "모르겠어요"를 누르면 기대 답안
  4. 내 답변에서 이어지는 꼬리질문: 페이지에서 가장 강조하는 섹션. 이 섹션 하나만 반대 테마 바탕이고, 스크롤에 따라 꼬리질문 단계가 하나씩 이어진다
  5. 점수에 맞춰 돌아오는 복습: 복습할 질문 목록과 숙련도가 오르내리는 모습
  6. 숫자로 남는 기록과 약한 주제: 꼬리잇기·복습 대기·이번 주·약한 주제 타일과 최근 기록
  7. 내 프로젝트 README로 만드는 예상 질문: README 예시와 만들어진 질문 5개
  8. 가입 전에 풀어 보는 한 문제: **맨 아래에 체험이 바로 붙어 있다**. 분야를 고르면 샘플 질문을 보여주고 "{분야}로 시작하기"
  9. 푸터: 이용약관 · 개인정보처리방침 · 피드백 보내기
  - 헤더는 로고, 테마 토글, 로그인, 시작하기.
  - **말투**: 첫 문장과 섹션 제목은 마침표 없이 명사로 끝내고, 설명·안내·버튼은 해요체로 쓴다(2026-10-28). 앱 화면은 그대로 해요체다.
  처음엔 랜딩과 체험 분야 고르기가 따로 있었으나, 랜딩에 서비스 소개가 없어 밋밋하다는 이유로 합쳤다 (2026-10-22). 디자인을 C안으로 바꾸면서 마퀴, 대화 예시, 기능 6칸, 진행 방식, 꼬리잇기(여우와 잔디) 섹션을 더했다 (2026-10-25). 2026-10-28 디자인 리셋에서 지금 구성으로 바꿨고, 첫 화면의 직접 눌러 보는 채점 데모(채점해 보기 → 점수 → 꼬리질문)는 뺐다. 직접 해 보는 것은 맨 아래 체험 한 곳이다.
- **랜딩 테마**: 다크로 시작하고 헤더의 토글로 라이트로 바꿀 수 있다.
- **체험**: 먼저 분야 하나(공통 CS / 백엔드 / 프론트엔드)를 고르고, 그 분야의 샘플 질문 1개로 답변 → 채점 → 꼬리질문 1개까지 해본다. 끝나면 가입을 권한다.
- **체험 이어받기**: 체험한 날(한국 시간) 안에 같은 브라우저에서 가입하면 체험 세션이 **첫 기록**으로 넘어간다. 그날의 오늘의 질문으로 인정되어 꼬리잇기 1일로 시작하고, 결과에 따라 복습 상자에 들어간다. 온보딩의 연습 범위에는 체험한 분야가 미리 선택돼 있다.
- 체험은 비용 때문에 **같은 브라우저는 하루 1번, 같은 IP는 하루 20번**까지로 제한한다. 처음엔 IP도 하루 1번이었으나, 부트캠프 강의실·회사처럼 한 IP를 여럿이 쓰는 곳에서 첫 사람 뒤로 전원이 막혀서 바꿨다 (2026-10-25, [08 설계](08-architecture.md)).

## 11. MY와 화면 공통

- **MY 탭**: 화면 제목은 "MY페이지"(띄어쓰기 없이. 화면 제목·브라우저 탭 제목이 같은 이름, 2026-10-27 #118). 모바일 하단 탭 라벨은 자리가 좁아 "MY"로 두고, 태블릿·PC는 상단 메뉴 오른쪽 끝의 프로필 원("MY페이지")으로 들어간다. 프로필(닉네임, 이미지, 편집), 휴식권·북마크 요약, 학습(리포트 `/report`, 북마크, 연습 범위 변경), 설정(알림 켜기·끄기와 시각, 화면 테마), 정보(이용약관·개인정보처리방침, 피드백 보내기), 맨 끝에 로그아웃(테두리 버튼)과 탈퇴. 꼬리잇기는 모든 앱 화면의 머리 막대에 있어 요약에서 뺐다.
  - **탈퇴로 들어가는 길은 목록 맨 끝의 작은 빨간 글자 링크 "탈퇴하기"다.** 탈퇴 화면(1번)의 실행 버튼 "탈퇴하기"는 빨간 바탕 + 흰 글씨를 그대로 쓴다. 처음엔 로그아웃(흰 배경 + 빨간 글씨)과 탈퇴(빨간 배경 + 흰 글씨) 큰 버튼을 나란히 두었으나(#118), 2026-10-28 디자인 리셋에서 실행 버튼만 빨간 바탕으로 남기고 들어가는 길은 글자 링크로 바꿨다. 프로젝트 삭제도 같다(9번).
- **홈 인사**: "OO님, 오늘도 한 문제 도전해 볼까요?"
- **문구 원칙**: 딱딱하거나 기계적인 말투를 피하고 사용자 이름을 부른다 (예: 입력칸 "OO님의 생각을 자유롭게 적어보세요").
- **AI 전송 고지**: 입력 화면마다 알리지 않는다. 가입할 때 동의(S06)와 개인정보처리방침(S09)에서 답변이 채점을 위해 해외(미국) AI 서비스로 전송된다는 것을 알린다. 처음엔 입력 화면마다 "입력한 내용은 AI 서비스로 전송돼요"를 한 줄로 넣었으나, 매번 반복돼서 뺐다 (2026-10-23). 로그인 없이 하는 체험은 가입 동의를 거치지 않으므로, 랜딩 "바로 체험" 아래 안내에 "답변은 AI 채점을 위해 전송돼요"를 함께 적는다.
- **약관과 정책(S09)**: 이용약관·개인정보처리방침 탭을 바꿔도 이력을 쌓지 않는다. 왼쪽 위 뒤로는 들어온 화면(MY·랜딩)으로 바로 간다. 처음엔 탭마다 이력이 쌓여 뒤로를 여러 번 눌러야 했다 (2026-10-27, #118).
- **다크 모드**: 처음엔 기기 설정을 따르고, 설정에서 라이트 / 다크 / 기기 설정을 고른다. 색은 처음부터 두 테마를 함께 설계한다 (6단계 UI 디자인).

## 12. 운영과 측정 (H-1~H-3, I-1, 비기능)

- **질문 은행**: 질문마다 분야, 세부 주제, 난이도, 채점 기준(핵심 키워드), 모범 답안, 참고 자료 링크(공식 문서 1~3개)를 가진다. 첫 출시까지 분야별 50개 이상, 합쳐서 150개 이상. 관리자 화면 없이 관리한다.
- **피드백**: 로그인한 뒤에는 MY의 정보 목록에 "피드백 보내기" 줄을 두고, 로그인 전 화면(랜딩, 로그인, 약관과 정책, 공유 페이지)은 모두 같은 푸터(이용약관 · 개인정보처리방침 · 피드백 보내기)를 둔다. 로그인한 뒤의 앱 화면(탭, 하위 화면, 면접, 결과, 운영)에는 푸터가 없고 약관과 피드백은 MY에서 찾는다. 채점 결과와 질문 상세의 "질문이나 채점에 문제가 있나요?"는 분류 "신고"와 질문 번호를 채운 채 피드백 화면을 연다(4번, #134). 처음엔 모든 화면 하단에 피드백 링크를 두었으나 탭 화면에서는 뺐고 (2026-10-27), 그 뒤 PC 앱 화면 오른쪽 아래에 떠 있는 여우 피드백 버튼을 두었으나 2026-10-28 디자인 리셋에서 마스코트와 함께 뺐다. 같은 리셋에서 로그인 뒤 화면에 남아 있던 푸터도 걷어냈다.
  - 앱 안 피드백 화면(`/my/feedback`)에서 분류(바라는 기능 · 버그 · 신고 · 기타, 기본은 기타)를 고르고 5~1000자로 보내고, 한 사람이 24시간에 5개까지 보낸다. 로그인해야 보낼 수 있다(로그인 전 화면에서 누르면 로그인 뒤 돌아온다). 보낸 사람은 다시 읽지 못하고 운영자만 운영 대시보드의 "사용자 피드백" 칸과 목록(`/admin/feedback`)에서 읽는다. 누가 보냈는지는 보여주지 않는다. 처음엔 저장소 이슈로 받았으나 GitHub 계정이 없는 사용자는 보낼 수 없고 공개 게시판이라 바꿨다 (2026-10-27, #15·#101).
  - 분류는 운영에서 나눠 보려고 넣었다. 대시보드 칸에 분류별 개수와 최근 3개의 분류 배지를, 목록에 분류 배지와 분류 필터(`?category=`)를 둔다. 처음엔 분류 없이 받았고, 그때 받은 피드백은 기타로 둔다 (2026-10-27, #118).
- **하루 사용 상한**: AI 비용을 묶기 위한 장치다. 숫자는 [09 채점](09-grading.md) 5장: 프로젝트 질문 생성 하루 1회, 프로젝트 질문 연습 하루 3세션, 다시 채점 세션당 3번.
  - **오늘의 질문 세션 1개는 상한과 상관없이 항상 보장**한다(채점 실패 시 다시 채점 포함). 서비스의 핵심인 "매일 1문제"와 꼬리잇기가 부가 기능 때문에 막히면 안 된다.
  - 개인 상한은 **내 프로젝트 질문 생성과 프로젝트 질문 연습**에만 건다.
  - 상한은 **시작하기 전에** 확인한다. 남은 한도가 없으면 시작 버튼 대신 "오늘은 사용 한도를 모두 썼어요. 내일 다시 만나요"를 보여준다. 답을 다 쓴 뒤에 막히는 일은 없어야 한다.
  - 세션을 시작할 때 그 세션에 필요한 몫을 미리 떼어 두어, 이미 시작한 세션은 꼬리질문 중간에 끊기지 않는다.
  - **서비스 전체 월 예산**($20, 약 2.8만 원)은 비상 브레이크다. 예산에 닿으면 오늘의 질문을 포함한 모든 AI 기능을 시작 전에 같은 문구로 막는다. 이미 시작한 세션은 끝까지 한다. 처음엔 1만 원이었다 (2026-10-26에 올림).
  - 예산의 **80%를 넘으면** 막기 전에 한 단계 낮춘다: 새로 시작하는 세션의 본 질문 채점도 꼬리질문처럼 가벼운 모델로 한다. 서비스가 멈추는 날을 줄이는 대신 그 기간엔 점수가 조금 덜 정확하다. 화면에는 따로 알리지 않는다 (2026-10-26).
  - 체험은 따로 같은 브라우저 하루 1번, 같은 IP 하루 20번으로 제한한다(10번).
  - 처음엔 "제출할 때 상한을 확인"하는 방식이었으나, 답을 다 쓰고 막히는 경험이 나빠서 바꿨다 (2026-10-21).
  - 안내 문구(S26, 2026-10-27): 내 프로젝트 화면은 Figma C안 S26대로 "오늘 프로젝트 연습 한도를 모두 썼어요 / 프로젝트 연습은 내일 다시 할 수 있어요. 오늘의 질문은 한도 없이 풀 수 있어요."를 보여준다. 등록 한도만 다 썼으면 같은 모양으로 "프로젝트 등록"을 넣어 보여주고 등록 버튼을 막는다. 질문 목록에서는 새 연습만 막고 하던 연습은 이어 할 수 있다. 등록 화면에 바로 들어와도 입력칸 대신 안내를 보여준다(README를 다 쓴 뒤에 막히지 않게). 월 예산에 닿으면 홈·내 프로젝트 모두 위의 "오늘은 사용 한도를 모두 썼어요. 내일 다시 만나요"를 쓴다(오늘의 질문도 막히므로 "오늘의 질문은 풀 수 있어요"를 붙이지 않는다).
- **지표 이벤트**: 첫 방문, 체험 시작·완료, 가입, 세션 시작, 본 질문 제출, 세션 완료, 👍/👎, 공유, 알림 클릭.
- **법적 페이지**: 이용약관, 개인정보처리방침.
- **운영 대시보드**(`/admin`): 운영자가 성공 지표(01 프로젝트 정의)와 채점·질문 은행 상태를 한 화면에서 본다. 읽기 전용이고, 서버 환경변수 `ADMIN_USER_IDS`에 든 계정만 들어가며 나머지는 404로 숨긴다. 운영자에게만 태블릿·PC 상단 메뉴 끝에 "운영", 모바일 머리 막대에 대시보드(방패) 아이콘이 보인다. 화면은 사용자 화면과 같은 모양에 강조색만 남색으로 바꾸고 머리 막대에 "운영" 표시를 단다(07 UI 디자인). 이번 주 답변 제출 수와 최근 8주 추이, 가입·온보딩 완료, 이번 주 답한 사람, D7 재방문(방문 기록 전까지는 가입 다음 날부터 7일 안에 다시 답한 비율), 👍 비율, 채점 실패율, 점수 분포, 꼬리질문 판정, 복습 대기·북마크, 분야별 공개 질문 수(목표 50개)를 보여준다. 사용자 피드백 최근 3개를 보여준다. AI 비용은 이번 달 합계를 예산 대비 %로 보여주고(80%를 넘으면 경고색, 원화는 `KRW_PER_USD`로 환산, #43), 첫 방문→첫 답변 전환은 기록이 생기면(#44) 채우고 그 전엔 "준비 중" 자리만 둔다. 질문을 고치는 관리자 화면은 여전히 다음 버전이다 (2026-10-27).

### 화면 공통 구조

- **탭 5개**: 홈 · 내 질문 · 리포트 · 프로젝트 · MY. 모바일은 위 머리 막대(로고 · 꼬리잇기) + 하단 탭 5개, 태블릿·PC는 위 한 줄 메뉴(로고 · 홈 · 내 질문 · 리포트 · 프로젝트 · 꼬리잇기 · 프로필 원)이고 프로필 원이 MY로 간다. 리포트는 홈의 "약한 주제 →"와 MY 메뉴에서도 들어간다. 옛 복습·기록 주소(`/review`, `/history`)와 기록 상세에서는 내 질문 탭이 켜진다.
- 처음엔 리포트를 기록 탭 안에서 "기록 / 리포트"로 나누고 기록의 필터·월 선택을 드롭다운으로 두었다. 리포트를 기록과 나란한 별도 화면으로 빼기로 했고, 다크 테마에서 기본 드롭다운 목록이 하얗게 떠 읽기 어려워 칩으로 바꿨다 (2026-10-27). 그 뒤 탭은 홈 · 복습 · 기록 · 프로젝트 · MY였고 리포트는 탭 밖에 있었으나, 2026-10-28 디자인 리셋에서 복습과 기록을 "내 질문"으로 합치고 그 자리에 리포트를 넣었다.
- 처음엔 탭 4개에 설정을 홈 오른쪽 위에 두었으나, 프로필·북마크·설정을 한곳에 모으려고 MY 탭을 추가했다 (2026-10-22).
- 머리 막대 아래에는 1px 구분선을 둔다. 탭 화면의 제목은 모바일·태블릿은 머리 막대 아래 제목 줄, PC는 화면 안의 큰 제목이다.
- 세션, 등록, 상세처럼 한 가지 일에 집중하는 화면에는 모바일 하단 탭을 두지 않는다(화면이 뒤로 버튼 머리를 그린다). 면접과 결과 화면은 모든 폭에서 메뉴 없이 닫기 버튼이 있는 전용 머리를 쓴다.
- 없는 주소와 화면 오류는 영문 기본 화면 대신 한국어 안내를 보여준다: "페이지를 찾을 수 없어요 / 주소가 바뀌었거나 지워진 페이지예요." + 홈으로, "화면을 불러오지 못했어요 / 잠시 뒤에 다시 시도해 주세요." + 다시 시도하기 · 홈으로. 앱 안의 오류는 메뉴를 남긴 채 보여준다.
- 색, 아이콘, 그림자, 카드 모양, 잔디 애니메이션 같은 시각 요소는 6단계 UI 디자인에서 정한다.

## 개발 순서

뒤 기능이 앞 기능에 기대므로 이 순서로 만든다.

1. **기반**: 공통 레이아웃·테마(라이트·다크) → 로그인·계정·프로필 → 질문 은행 구조 → 온보딩
2. **핵심 흐름**: 오늘의 질문 선정 → 답변·채점 → 꼬리질문 세션 → 복습
3. **습관 장치**: 기록·북마크 → 꼬리잇기·잔디 → 웹 푸시 → 약점 리포트
