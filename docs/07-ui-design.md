# 07. UI 디자인 방향

와이어프레임(#7)의 구조 위에 입히는 시각 기준이다. 색과 로고는 [06 브랜드](06-brand.md)를 따른다.

**지금 기준은 2026-10-28 디자인 리셋이다.** 기능·데이터·API·동작은 그대로 두고 화면 디자인만 처음부터 다시 잡았다. 무채색 바탕에 시그널 오렌지 하나, 유리·카드 겹치기 없이 1px 선과 여백으로 나눈 평평한 면, 모노 글꼴 숫자가 특징이다. 마스코트 없이도 서는 화면을 목표로 했다.

**기준값은 코드다.** 색은 `lib/theme.ts`, 모서리·그림자·모션 같은 나머지 값은 `app/globals.css`에 있고, 대비는 `tests/contrast.test.ts`로 확인한다. 아래 표는 그 요약이다. 이전 안의 Figma 파일 [TailQ · C안 디자인](https://www.figma.com/design/hQbw6ijIVjsloaeUy52iQi)과 [TailQ](https://www.figma.com/design/wPjTOU5FJdhdrMWOGZTHdh)의 화면 페이지는 기록으로 남겨 둔다.

## 디자인이 바뀐 과정

| 시기 | 안 | 특징 | 바꾼 이유 |
|---|---|---|---|
| 2026-10-22 | 차분한 UI | 중립 회색, 강조색 하나, 면색 카드 | 흔한 UI 라이브러리 기본 모양과 같아서 밋밋하고 어디서 본 화면이 됐다 |
| 2026-10-22~23 | 개발자 노트 | 고정폭 메타 정보, 상자 대신 구분선, 랜딩만 유리·3D | 정돈됐지만 서비스만의 인상이 약했다 |
| 2026-10-25~27 | C안 | 앱까지 유리 질감, 3D Q가 면접관으로 등장, 녹색 기운의 배경 빛, 민트 강조, 다크·라이트 토글 | 기존 취향과 상관없이 새 방향을 만들어 보고 고른 안 |
| 2026-10-28~ | **리셋** | 무채색 + 시그널 오렌지 하나, 평평한 면과 1px 선, 화면당 큰 순간 하나, 모노 숫자, 20칸 점수 막대, 1px 숫자 타일, 꼬리질문 스레드 | 사용자 요청으로 API를 해치지 않는 선에서 디자인을 전부 리셋했다. 평평한 면, 화면당 큰 순간 하나, 8px 버튼, 크기 따라 좁아지는 자간은 참고 서비스(iKala)에서 가져왔다. 색은 남색·파랑 시안과 시그널 오렌지 시안을 비교해 오렌지를 골랐고, 20칸 점수 막대와 1px 숫자 타일은 다른 시안에서 가져와 섞었다 |

개발자 노트 방향에서 남긴 것: 질문 번호·분야 태그·날짜·숫자의 **고정폭 글꼴**, 상자 대신 구분선, 화면마다 시선이 처음 갈 곳 하나.

## 디자인 토큰

CSS 변수로 두고 라이트·다크는 같은 이름에 값만 바꾼다(`[data-theme="dark" | "light"]`). 컴포넌트에는 색 값을 직접 쓰지 않는다. 앱은 기기 설정을 따르고 MY에서 라이트 / 다크 / 기기 설정을 고른다. 랜딩은 고른 테마가 없으면 다크로 시작하고 헤더 토글로 바꾼다.

| 토큰 | 라이트 | 다크 | 쓰는 곳 |
|---|---|---|---|
| `--canvas` | `#F3F4F2` | `#0E0F0E` | 페이지 바탕, 대화상자·시트 바탕 |
| `--surface` | `#FFFFFF` | `#171918` | 보조 면: 숫자 타일, 채점 결과 묶음, 입력 영역, 태블릿·PC 머리 막대 |
| `--text` | `#111312` | `#EDEEEC` | 제목·본문 강조, 잘 답했어요, 높은 점수 |
| `--text-sub` | `#5B605D` | `#A4A9A5` | 본문, 이름표, 조금 부족해요 |
| `--text-muted` | `#6A6F6B` | `#8A8F8B` | 보조 글자, 메타 정보, 모르겠어요 |
| `--line` | `#DCDEDB` | `#262927` | 구분선, 숫자 타일 사이 선 |
| `--line-strong` | `#C5C8C5` | `#3A3E3B` | 장식 선만: 스레드 세로 선, 앞으로 올 날 테두리 |
| `--mark-empty` | `#868A87` | `#6A6E6A` | 빈 칸·빈 날·남은 단계 테두리, **입력칸·보조 버튼·칩 테두리** (그래픽 대비 3:1) |
| `--primary` / `--on-primary` | `#FF4F12` / `#111312` | `#FF5A1F` / `#0E0F0E` | 주 버튼 바탕·글자. 글자가 들어간 면에만 |
| `--accent` | `#B83505` | `#FF7A45` | 오렌지 글자·링크, 선택 표시, 포커스 링, 진행 막대·달력 칸 같은 얇은 표시 |
| `--accent-soft` | `#FFEDE4` | `#2A1810` | "오늘의 질문"·"오늘 다시" 라벨 바탕, 선택한 칩 바탕 |
| `--danger` | `#B0123B` | `#FF6B86` | 틀렸어요, 낮은 점수, 오류 글자, 삭제·탈퇴 글자 링크 |
| `--danger-fill` / `--on-danger` | `#B0123B` / `#FFFFFF` | `#B0123B` / `#FFFFFF` | 삭제·탈퇴 실행 버튼 |
| `--scrim` | `rgba(17,19,18,0.4)` | `rgba(0,0,0,0.6)` | 대화상자·시트 뒤 가림막 |

- **오렌지 두 가지**: 밝은 `--primary`는 주 버튼처럼 글자가 들어간 면에만 쓰고, 막대·점·선·글자는 진한 `--accent`를 쓴다. 밝은 오렌지를 얇게 쓰면 그래픽 대비 3:1이 나오지 않는다. 오렌지 위 글자는 늘 어두운 잉크색이다.
- **오렌지를 쓰는 곳**: 지금 할 일(주 버튼), 오늘(오늘의 질문·오늘 다시 라벨, 이번 주의 오늘), 이어 가기(꼬리잇기 달력 칸), 선택·포커스. 넓은 면을 칠하지 않고, 실패를 오렌지로 표시하지 않는다.
- **점수 구간**: 70 이상 `--text` + 채운 원, 40~69 `--text-sub` + 반쪽 원, 40 미만 `--danger` + 네모. 구간은 `app/interview/verdict.ts`의 `scoreColor`(09 채점 기준)다. 색만으로 말하지 않도록 모양 점을 늘 함께 쓴다.
- **입력칸·보조 버튼 테두리**는 `--mark-empty`다. 처음엔 `--line-strong`이었는데 대비가 라이트 1.5~1.7:1, 다크 1.6~1.8:1로 WCAG 1.4.11(3:1)에 못 미쳐 바꿨다(2026-10-28). `--line-strong`은 장식 선에만 남겼다.
- 글자 쌍은 바탕·surface 위에서 4.5:1 이상, 빈 칸 테두리는 3:1 이상이다(`tests/contrast.test.ts`).
- **운영 화면**(`/admin`): 같은 토큰을 쓰고 `--accent`·`--accent-soft`만 남색(라이트 `#2E45B8` / `#E6EBFF`, 다크 `#8FA8FF` / `#151B33`)으로 덮어쓴다. 머리 막대에 "운영" 라벨을 단다. 값은 `lib/theme.ts`의 `ADMIN_TOKENS`이고, 보이는 운영 화면이 있을 때만 덮어쓴다(숨겨진 채 문서에 남은 운영 화면은 빼고 센다). 처음엔 배경·유리·점수 색까지 남색이었다 (#104).

### 면과 선

| 종류 | 규칙 |
|---|---|
| 구획 | 상자 대신 1px `--line` 구분선과 여백. 큰 묶음(목록·표)의 머리에는 2px `--text` 선 |
| surface 면 | 숫자 타일 묶음과 채점 결과 묶음에만 깐다. 카드 안에 카드를 넣지 않는다 |
| 숫자 타일 | 묶음 바탕을 `--line`으로 칠하고 1px 간격을 두어 타일 사이 선을 만든다 |
| 그림자 | `0 12px 32px rgba(17,19,18,0.18)` 하나. 대화상자·바텀시트·토스트·말풍선에만. 버튼·목록·구획은 평평하다 |
| 흐림 | `backdrop-filter`는 쓰지 않는다 |

## 서비스 고유 요소

| 요소 | 모양 |
|---|---|
| **꼬리질문 스레드** | 세로 1px `--line-strong` 선 위에 단계 점(본 질문 → 꼬리질문 1·2·3)과 단계 이름, 질문, 결과(본 질문은 점수, 꼬리질문은 판정). 지금 단계 점은 `--accent`에 4px 옅은 링. 면접 화면 PC 왼쪽 4칸, 오늘의 결과의 단계별 목록(2px 머리선 아래), 랜딩 꼬리질문 섹션에 같은 모양을 쓴다 |
| **판정 모양 점** | 작은 점 + 판정 글자. 잘 답했어요 채운 원(`--text`) · 조금 부족해요 반쪽 원(`--text-sub`) · 틀렸어요 네모(`--danger`) · 모르겠어요 빈 원(`--text-muted`). 점은 그림이고 뜻은 글자가 전한다 |
| **20칸 점수 막대** | 5점마다 한 칸, 칸 사이 2px, 모서리 1px. 채운 칸 `--text`, 빈 칸 `--mark-empty` 1px 테두리. 채점 결과는 높이 10, 요약 타일·홈 오늘 완료는 6 |
| **점수** | 큰 모노 숫자 + `/100` + 점수 막대. 숫자 색은 점수 구간 색. 꼬리질문은 점수 대신 판정. 모르겠어요는 "–" |
| **숫자 타일** | 1px 선으로 나뉜 타일 묶음. 한국어 이름표 + 큰 모노 숫자 + 보조 글. 홈 학습 현황(이번 주 · 약한 주제), 오늘의 결과(본 질문 점수 · 꼬리잇기 · 다음 복습 3칸). 이동이 있는 타일은 이름표 끝에 → |
| **진행 단계** | 면접 머리 가운데의 단계 막대(끝난 단계 `--text`, 지금 `--accent`, 남은 단계 `--mark-empty` 테두리)와 "본 질문 → 꼬리질문 n" 글자. 온보딩 단계 표시도 같다 |
| **질문 번호** | `Q.042 · backend / jpa`처럼 모노 번호와 분야 태그. 프로젝트 질문은 프로젝트 이름(본문 글꼴) |
| **라벨** | 누를 수 없는 알약. 오늘(`--accent-soft` 바탕 + `--accent` 글자: 오늘의 질문, 오늘 다시) · 중립(`--line` 테두리 + `--text-sub`: 내일 다시, N일 뒤 다시, 복습 완료) · 개념(surface 바탕: 보완할 개념, 코드 식별자는 모노) |

## 화면

### 앱 (모바일 375 기준)

흐름: **홈 → 면접(본 질문 → 꼬리질문 1·2·3) → 오늘의 결과**. 한 화면에 큰 순간은 하나다: 홈은 오늘의 질문, 면접은 지금 질문, 결과는 마무리 문장.

- **머리 막대**: 모바일은 위 56px(워드마크 30 · 꼬리잇기, 운영자는 방패 아이콘) + 하단 탭 5개. 태블릿·PC는 위 64px 한 줄(워드마크 34 · 홈 · Q노트 · 리포트 · Q메이커 · 꼬리잇기 · 프로필 원)이고 프로필 원이 MY로 간다. 아래에 1px 구분선.
- **홈**: 인사("테일러님, 오늘 면접 잘 봐요") / "오늘의 질문" 라벨 + 질문 번호 / 질문(display, 상자 없이 큰 글) / 주 버튼 "시작하기" + "새 질문 · 약 5분" / 첫 방문 안내(처음 한 번, 주 버튼 아래, "TailQ는 이렇게 써요" 세 줄과 "알겠어요" · 같은 줄 오른쪽에 설치할 수 있는 브라우저면 "앱 설치"(ghost, 앞에 download 아이콘)) / 학습 현황 타일(이번 주 · 약한 주제 →) / 복습할 질문 3개("Q노트에서 보기 →"). 복습 줄은 복습 시기 · 질문 · 최근 점수 · 숙련도이고, 모바일은 위 줄(복습 시기·점수·숙련도) + 아래 줄(질문) 두 줄이다. 오늘 완료면 질문(3줄까지) · 점수와 막대 · "결과 다시 보기"(보조 버튼) · 다음 복습.
- **면접**: 전용 머리(닫기 · 진행 단계 · 북마크, 메뉴 없음) / 지금 질문(display) / 답변 입력(surface, `--mark-empty` 테두리, 17px) / "모르겠어요"(보조 버튼) · 글자 수 · "제출하기"(주 버튼). PC는 12칸 격자에 왼쪽 4칸 스레드, 오른쪽 8칸 질문·답변.
  - 채점 중: 제출 버튼 안 진행 표시 + 점수 자리 "··".
  - 본 질문 결과: 지금 질문이 작게 접히고 채점 결과 묶음(surface: 점수 · 막대 · 판정 · 한 줄 평 · 잘한 점 · 보완할 점 · 보완할 개념)이 펼쳐진다. 모범 답안과 참고 자료만 접어 두고(모르겠어요면 펼친 채), 그 아래 "이 채점이 도움이 됐나요?" · 주 버튼 "꼬리질문 받기"(마지막은 "오늘의 결과 보기") · "질문이나 채점에 문제가 있나요?" 링크.
  - 꼬리질문 결과: 판정 모양 점 + 한 줄 피드백. 기대 답안은 잘 답했으면 접고, 부족·틀림·모르겠어요면 펼친다.
- **오늘의 결과**: 마무리 문장("오늘 면접도 고생 많았어요") / 요약 타일 3칸(본 질문 점수 · 꼬리잇기 · 다음 복습) / 단계별 결과 스레드 / "결과 공유하기"(보조) · "홈으로"(주) 한 줄.
- **Q노트**: 제목 · "질문 N개 · 오늘 복습 N개" · 필터 칩 5개(오늘 복습 · 이번 주 · 북마크 · 복습 완료 · 전체, 개수 포함) / 질문 줄(복습 시기 라벨 · 질문과 번호·주제·푼 횟수 · 최근 점수 · 숙련도). 질문 상세는 복습 상태와 날짜별 기록 줄(날짜 · 점수).
- **Q메이커**: 제목 · 설명 · 구획 탭(프로젝트 / 학습 자료) · 등록한 목록 · 등록 버튼(구획마다 주 버튼 하나) · 한도 안내 두 줄. PC는 오른쪽에 그 구획이 비었을 때만 "이렇게 연습해요" 안내 열.
- **MY**: 프로필 · 휴식권·북마크 타일 · 학습 / 설정 / 정보 목록(2px 머리선) · 맨 끝 "로그아웃"(보조 버튼)과 "탈퇴하기"(빨간 글자 링크). 설정 맨 끝 줄은 설치할 수 있을 때만 "앱 설치 / 홈 화면에 추가해요"(다른 설정 줄과 같은 모양, 설치 창이 떠 있는 동안 "설치하는 중이에요").
- **앱 설치 자리(#150)**: 버튼은 서버와 첫 그림에서는 없고 브라우저가 판정한 뒤 나타난다. 홈은 "알겠어요"와 같은 줄이라 카드 높이가 변하지 않고, MY는 설정 맨 끝이라 위 줄이 밀리지 않는다(`/my`를 바로 열면 아래 "정보" 구획만 한 번 내려갈 수 있다). 빈자리를 미리 잡지 않는다(설치 못 하는 브라우저에 빈 구멍이 남는다). 좁으면 버튼 줄을 바꾼다.
- **아이폰 설치 안내 창**: MY 확인 창과 같은 가운데 창(`min(400px, 100% - 40px)`, 패널 모서리, 가림막). 제목 "홈 화면에 추가하기" · 알림 이점 한 줄 · 번호 01~03 단계(번호 13 mono muted, 글 15 text-sub, 핵심 낱말 700) · 단계마다 아래에 사진 없이 그린 정지 그림(1px mark-empty 테두리, 8px 모서리 상자: 공유 아이콘 44×44 / "홈 화면에 추가" + 네모 더하기 아이콘 / "추가") · 마지막 안내 한 줄 · "닫기"(보조 버튼, 전체 폭). 열면 "닫기"에 초점, Esc·바깥 누름·닫기로 닫으면 설치 버튼으로 초점이 돌아온다. 그림은 `aria-hidden`이고 뜻은 글이 전한다.
- **빈 상태·오류**: 그림 없이 한 줄 제목 · 설명 · 버튼. 404("페이지를 찾을 수 없어요")와 화면 오류("화면을 불러오지 못했어요" + 다시 시도하기)도 같은 모양이다.

### 랜딩 (반응형)

순서: 헤더 → 첫 화면(첫 문장 + 기기 틀 속 실제 화면) → 채점 → 꼬리질문(정점) → 복습 → 기록 → 학습 자료 → 체험 → 푸터. 한 사람의 하루를 실제 앱 화면 캡처로 따라간다(04 기능 명세 10번).

- **헤더**: 위에 붙어 따라온다. 워드마크 · 테마 토글 · 로그인 · 시작하기(보조 버튼). 랜딩의 주 버튼은 첫 화면 "로그인 없이 한 문제 풀어보기"와 체험 "{분야}로 시작하기"다.
- **첫 화면**: PC는 왼쪽 글, 오른쪽에 데스크톱 홈을 넣은 노트북 틀(뒤)과 74점 채점 결과를 넣은 휴대폰 틀(앞). 휴대폰 폭에서는 휴대폰만. 기기 틀은 페이지에서 여기뿐이고, 나머지 섹션은 캡처에서 블록 하나만 잘라 틀 없이 놓는다. 직접 눌러 보는 채점 데모는 없다.
- 처음엔 첫 화면 아래에 실제 질문 예시 두 줄이 60초에 한 바퀴 흐르는 질문 띠가 있었으나, 실제 화면 캡처 구성으로 바꾸며 지웠다 (2026-10-29, #149).
- **꼬리질문(정점)**: 페이지에서 이 섹션 하나만 반대 테마 토큰으로 바탕을 뒤집는다(오렌지 면이 아니다). 앞에 페이지에서 가장 긴 빈 바탕을 두고, 화면이 충분히 높으면 섹션이 긴 트랙이 되어 스크롤에 따라 단계가 하나씩 이어진다.
- 섹션 간격은 80(모바일 56). 모바일도 같은 순서를 한 열로 쌓는다.

## 모션

| 항목 | 값 |
|---|---|
| hover·눌림 | 120ms |
| 펼침·화면 안 전환·대화상자 | 200ms |
| 곡선 | `cubic-bezier(0.2, 0, 0, 1)` 하나 |
| 버튼 누름 | `scale(0.98)` |
| 화면 등장 | 아래 8~16px에서 올라오며 페이드(200ms) |
| 테마 전환 | 배경·글자 200ms. 랜딩 토글 아이콘은 해·달이 돌며 작아지고 커지며 엇갈려 바뀐다 |
| 점수 | 0에서 점수까지 18ms마다 2씩, 막대도 같이 차오른다(점수가 나오는 모든 화면) |
| 랜딩 | 첫 화면은 노트북이 아래 24px에서 900ms, 휴대폰이 200ms 늦게 아래 64px에서 900ms에 떠오른다(캡처 decode를 최대 600ms 기다린 뒤). 섹션 글과 캡처는 화면에 들어올 때 한 번 아래 24px(모바일 16px)에서 700ms에 나타나고, 글 → 캡처 → 둘째 캡처 순으로 150ms씩 늦는다. 꼬리질문 섹션은 스크롤에 묶여 단계가 이어지고, 학습 자료 녹화는 보일 때만 재생한다 |

- **동작 줄이기**가 켜져 있으면 전환·애니메이션을 모두 끈다. 눌림은 크기 대신 투명도(0.72)로 보여 주고, 점수는 바로 최종 값, 랜딩 녹화는 마지막 장면 그림으로 바뀐다.
- 빠르게 번쩍이는 효과, 숨쉬기·부유 같은 반복 장식은 쓰지 않는다. 스크롤 스냅은 쓰지 않는다.
- CSS로 만든다.

## 상호작용 상태

| 상태 | 모양 |
|---|---|
| hover (PC) | 주 버튼은 어두운 글자색을 8% 섞어 진하게, 삭제 버튼은 밝기 0.92. 보조·글자 버튼, 아이콘 버튼, 칩, 목록 행은 surface 바탕. 삭제·탈퇴 글자 링크는 밑줄 |
| 누름 | `scale(0.98)`, 목록 행은 surface 바탕 유지 |
| 포커스 (키보드) | 2px `--accent` 링에 2px 간격. outline을 지우지 않는다 |
| 비활성 | 투명도 0.4, 커서 기본 |
| 처리 중 | 글자 대신 진행 표시, 폭 유지, 다시 누를 수 없음. 화면을 떠났다 돌아오면 처리 중이 아닐 때 잠금을 푼다 |
| 선택 (칩) | `--accent-soft` 바탕 + 1px `--accent` 안쪽 테두리 + `--accent` Bold 글자 |

- hover는 마우스가 있는 기기(`@media (hover: hover)`)에서만 붙인다. 터치 뒤에 hover 모양이 남지 않게 하려는 것이다.
- 누를 수 있는 것은 모두 hover, 포커스, 눌림 상태를 갖는다.

### 버튼 규칙

- **주 버튼**: 화면마다 하나만 채운다. `--primary` 바탕에 어두운 `--on-primary` 글자, 높이 52, 모서리 8, 16 Bold. 대화상자·묶음 안은 44.
- **보조 버튼**: 투명 바탕 + `--mark-empty` 1px 테두리 + `--text` 글자, 높이 44. **글자 버튼**은 바탕 없이 글자만, 높이 44.
- **삭제·탈퇴**: 확인 창이나 탈퇴 화면으로 들어가는 길은 목록 끝의 작은 빨간 글자 링크(`--danger`, 14, 터치 영역 44). 실행 버튼은 `--danger-fill` 바탕 + 흰 글자. 프로젝트 삭제는 확인 창에서 프로젝트 이름을 똑같이 써야 켜진다.
- **배치**: 대화상자는 가로 2개 같은 폭, 순서 [취소] [실행]. 결과 화면은 [공유] [홈으로] 한 줄. 화면 아래 묶음은 주 버튼 + 보조 버튼.
- **칩**: 필터·선택지는 알약형, 높이 44, `--mark-empty` 테두리, 선택은 위 "선택" 상태. 분야 선택은 radio 패턴.
- **소셜 로그인**: 각 서비스의 대표 아이콘과 색을 쓴다. 카카오는 노란 바탕(`#FEE500`)에 검은 글씨, Google은 흰 바탕에 회색 테두리와 색깔 G, GitHub는 검은 바탕(`#24292F`)에 흰 글씨. 브랜드 색이라 테마가 바뀌어도 그대로다.
- C안에서는 알약형 유리 버튼이었고, 보조 행동을 글자형으로 두었다가 2026-10-26에 모든 행동을 버튼 모양으로 통일했었다.

## 접근성

- 아이콘 버튼에 `aria-label`. 테마 토글은 지금 상태가 아니라 "바꿀 모드"를 읽어준다.
- 분야·분류 선택은 `role="radiogroup"` + `aria-checked`. 점수는 `role="img"` + "100점 만점에 N점", 점수 막대·숙련도·진행 단계도 `role="img"`로 읽는다.
- 판정·점수 구간은 색만으로 말하지 않고 글자와 모양 점을 함께 쓴다.
- 글자 대비 4.5:1 이상, 입력칸·버튼 테두리와 빈 칸 표시 3:1 이상, 터치 영역 44px 이상, 글자 12px 이상.
- 지원 최소 폭 320, 200% 확대에서도 가로 스크롤 없이 다시 흐른다.

## 화면 문구

같은 자리에 이전 문구가 있으면 그대로 쓴다. 새 자리만 같은 형태로 쓴다: 해요체, 짧은 사실 문장, 숫자는 기능 명세에 있는 것만, 버튼은 동사로 끝낸다. 채점 결과는 잘한 점을 먼저, 보완할 점을 다음에 쓴다. 설득용 대비("A 말고 B"), 공감·훈계형 도입, 과장·의인화, 위로형 문장, 영문 대문자 섹션 라벨, 느낌표, 이모지는 쓰지 않는다.
