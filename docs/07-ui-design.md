# 07. UI 디자인 방향

와이어프레임(#7)의 구조 위에 입히는 시각 기준이다. 색과 로고는 [06 브랜드](06-brand.md)를 따른다.

**지금 기준은 C안이다** (2026-10-25). 유리 질감, AI 면접관 역할의 3D Q, 다크·라이트 토글이 특징이다.

**디자인 원본은 Figma [TailQ · C안 디자인](https://www.figma.com/design/hQbw6ijIVjsloaeUy52iQi)이다** (2026-10-26). 모바일 34·태블릿 33·PC 33 화면과 랜딩 PC·모바일이 다크·라이트로 모두 있다. 처음엔 C안 목업(앱 다크·라이트, 랜딩)을 원본으로 두었으나, 목업에 없던 화면까지 같은 부품으로 다 그린 뒤 이 파일을 원본으로 바꿨다. 이전 Figma 파일 [TailQ](https://www.figma.com/design/wPjTOU5FJdhdrMWOGZTHdh)의 화면 페이지(03~07)는 이전 안(개발자 노트)으로 남겨 둔다.

## 디자인이 바뀐 과정

| 시기 | 안 | 특징 | 바꾼 이유 |
|---|---|---|---|
| 2026-10-22 | 차분한 UI | 중립 회색, 강조색 하나, 면색 카드 | 흔한 UI 라이브러리 기본 모양과 같아서 밋밋하고 어디서 본 화면이 됐다 |
| 2026-10-22~23 | 개발자 노트 | 고정폭 메타 정보, 상자 대신 구분선, 랜딩만 유리·3D | 정돈됐지만 서비스만의 인상이 약했다 |
| 2026-10-25~ | **C안** | 앱까지 유리 질감, 3D Q가 면접관으로 등장, 녹색 기운의 배경 빛, 다크·라이트 토글 | 기존 취향과 상관없이 새 방향을 만들어 보고 고른 안 |

개발자 노트 방향에서 남긴 것: 질문 번호·분야 태그·날짜·글자 수·숫자의 **고정폭 글꼴**, 화면마다 시선이 처음 갈 곳 하나.

### C안으로 바꾸면서 정한 13가지

C안 목업이 기존 문서와 부딪힌 곳을 항목마다 골랐다. 전부 C안을 따른다.

| # | 항목 | 이전 규칙 | 지금 (C안) | 메모 |
|---|---|---|---|---|
| 1 | 유리 효과 | 랜딩, 앱은 하단 탭·모달 배경만 | 앱 카드·통계·바텀 시트·탭바까지 유리 | 유리 위 글자도 대비 4.5:1 이상을 지킨다 |
| 2 | 3D Q | 랜딩 첫 화면에만 | 앱 홈 카드와 면접 화면에 **AI 면접관**으로 상주 | 모바일·저사양·동작 줄이기에서는 정지 이미지 |
| 3 | 랜딩 테마 | 항상 다크 | 다크·라이트 토글, **기본은 다크** | 예전 라이트 랜딩은 어두운 첫 화면과 밝은 아래쪽이 섞여 어중간해서 폐기했었다. C안 라이트는 배경 빛까지 처음부터 따로 설계했다 |
| 4 | 모서리 | 카드 12 · 칩 6 | 카드 22~40, 시트 30, 버튼은 알약형 | 이전엔 "말랑해 보여서" 줄였지만, 유리 질감에는 둥근 모서리가 맞는다 |
| 5 | 카드 | 핵심 카드 하나만 면색, 나머지는 구분선 | 통계·목록·시트도 유리 카드 | 1번과 한 묶음 |
| 6 | 글자만 있는 버튼 | 쓰지 않고 버튼으로 통일 | 보조 행동은 글자형 버튼 ("홈으로", "다시 보기", "잘 모르겠어요") | 주 버튼 하나를 더 돋보이게 한다. 터치 영역은 높이 44 이상. **2026-10-26에 다시 버튼으로 통일했다** (아래 "전 화면을 그리며 더 정한 것" 1번) |
| 7 | 여우 | 상태 화면에만 작게(64~96) | 랜딩 꼬리잇기 섹션에 크게도 쓴다 | 06 브랜드의 "랜딩에 쓴다"와 같다 |
| 8 | 랜딩 카드 hover | 반전(흰 바탕 검은 글씨) | 4px 떠오름 + 강조색 테두리 링 | 반전은 유리 카드와 어울리지 않는다 |
| 9 | PC 랜딩 구성 | 큰 제목 → 단계 스크롤 → 큰 문장 → 실제 화면 → 체험 | 좌우 분할 히어로(인터랙티브 채점 데모) → 마퀴 → 대화 예시 → 벤토 → 진행 방식 → 여우 → 체험 | 좌우 분할은 예전에 "밋밋하다"고 버렸던 모양이지만, C안은 데모가 직접 움직이고 섹션이 많아 다르다 |
| 10 | 하단 탭 선택 표시 | 위쪽 짧은 표시줄 | 안쪽 유리 캡슐 | |
| 11 | 배경·중립색 | 중립 회색 (`#FFFFFF` / `#0E1013`) | 녹색 기운 (`#EAF1EE` / `#07100E`) + 배경 빛 덩어리 | 유리가 보이려면 배경에 빛이 있어야 한다 |
| 12 | 다크 강조색 | `#34C79A` 하나 | 글자·선 `#7CF2CD`, 버튼 채우기 `#34C79A` | 버튼과 글자의 강조색을 나눠 대비를 지킨다 |
| 13 | 디자인 원본 | Figma 07 페이지 | C안 목업 | Figma는 이전 안으로 남긴다. 2026-10-26부터는 목업을 바탕으로 전 화면을 그린 Figma C안 파일이 원본 |

### 전 화면을 그리며 더 정한 것 (2026-10-26)

목업에 없던 화면을 채우고, 그린 화면을 보며 고친 것이다.

| # | 항목 | 처음 | 지금 | 바꾼 이유 |
|---|---|---|---|---|
| 1 | 버튼 | 보조 행동은 글자형 버튼 (C안 6번) | 모든 행동은 버튼 모양. 같은 묶음의 버튼은 높이·모서리·글자 크기를 같게 (아래 "버튼 규칙") | 글자형과 버튼이 섞이니 버튼감이 들쭉날쭉했다 |
| 2 | 3D Q 반사·접지 그림자 | Q 아래 흐린 반사와 그림자 | 쓰지 않는다. 후광 + Q만 | 반사가 갑자기 붙은 장식처럼 어색했다 |
| 3 | 목록 카드 | 줄 사이 1px 구분선 | 구분선 없이 여백으로 묶는다 | C안 5번(묶음은 유리 카드)과 맞춘다 |
| 4 | 입력칸 | 라벨이 칸 안 위쪽, 넓은 칸 | 제목은 칸 밖 위(13 Bold), 칸 높이 52, 안내 글씨는 칸 밖 아래(12, 예: "2~12자로 입력해 주세요") | 칸이 쓸데없이 넓고 무엇을 몇 자 써야 하는지 안 보였다 |
| 5 | 보조 설명 글 | 줄 아래 늘 보임 | 제목 옆 원 안 느낌표 아이콘을 누르면 말풍선으로 (예: 프로필 공개 설명) | 필요할 때만 보는 정보다 |
| 6 | "모르겠어요" (면접) | 글자형 | 유리 알약 버튼(높이 36) | 1번과 같은 이유 |
| 7 | 복습 칩 (S18) | 칩의 역할을 정하지 않음 | 필터. 맨 앞 "전체 4"가 기본 선택 | |
| 8 | 꼬리잇기 달력 (S21) | 정하지 않음 | 기본 3개월(칸 18px, PC 24px), 주·월·3개월·1년 세그먼트. 주·월은 요일 머리 7열 달력에 날짜 표시. 1년은 모바일 가로 스크롤 + 왼쪽 끝 흐림. 칸 hover는 안쪽 outline(칸 틈으로 번지지 않게). 말풍선은 날짜 · 점수 / 기록 없음 / 휴식권 / 오늘 | 처음엔 최근 1년 잔디 하나(모바일·태블릿도 52주 전부, 가로 스크롤)였으나 칸이 작고 빽빽해 바꿨다(#117) |
| 9 | 기본 아바타 (S28) | 사람 아이콘 | 소셜 계정 사진 1 + 색 원 3개(민트·하늘·주황) 안에 닉네임 첫 글자 | |
| 10 | 토스트 (S34) | 한 화면에 예시 여러 개 | 실제처럼 하나만. 문구 5개는 따로 "토스트 문구" 보드(S34E) | |
| 11 | 고정폭 글꼴 | 숫자·메타 라벨 전부 | 한글이 들어간 라벨은 본문 글꼴 + `font-variant-numeric: tabular-nums`. 고정폭은 한글 없는 `Q.042`·`backend / jpa`·숫자에만 | 고정폭 안의 한글은 글자 사이가 벌어진다 |
| 12 | 랜딩 주 버튼 | 화면마다 하나 | 랜딩은 헤더·첫 화면·데모·체험 4개를 예외로 허용 | 목업 구성대로 둔다 |
| 13 | PC 홈 오른쪽 열 | 정하지 않음 (두 안) | 통계 카드 세로 + "이번 주"(월~일 7칸, 휴식권 빗금, 오늘 테두리) + "약한 주제"(평균 점수 막대) | |

### 실제 화면을 보고 고친 것 (2026-10-27, #114~)

데모 계정으로 실제 화면(27인치 모니터 풀 화면 포함)을 보고 정했다. Figma C안과 다른 곳은 이 표가 우선이다.

| # | 항목 | 처음 | 지금 | 바꾼 이유 |
|---|---|---|---|---|
| 1 | 배경 | 빛 덩어리 3개가 14초마다 떠돈다 | 기본은 화면 전체에 은은한 선형 그라디언트 두 겹(`--wash1` 왼쪽 위, `--wash2` 오른쪽 아래), 움직이지 않는다. 예전 빛 덩어리는 MY > 화면 테마 > 배경 "빛 번짐"으로 고를 수 있다(이 기기에 기억, `tailq-bg`) | 계속 보면 어지럽고 촌스러웠다. 좋아하는 사람을 위해 지우지 않고 선택지로 남겼다 |
| 2 | PC 내용 폭 | 사이드 메뉴 224, 내용 최대 992 | 화면 폭에 따라 넓힌다(아래 "PC·태블릿 앱"). CSS 변수 `--nav-w`·`--shell-left`·`--content-max` | 27인치 풀 화면에서 가운데로 몰려 빈 곳이 많았다 |
| 3 | 보조 글자 | `--sub`·`--muted`가 흐리고, 공통 부품 보조 글자 12~13 | 두 색을 한 단계 진하게(다크는 밝게), 공통 부품 보조 글자 14 이상(탭바 라벨 13) | 회색 부제가 작고 흐려 읽기 어려웠다 |
| 4 | 점수 색 | 높음 `#34C79A`, 중간 `#7CF2CD`(둘 다 초록), 낮음 앰버 | 높음 초록, 중간 앰버, 낮음 산호 | 74점과 "조금 부족해요"가 같은 색으로 보여 구간이 구분되지 않았다 |
| 5 | 테마 토글·알림 (PC) | 사이드 메뉴 맨 아래 | 내용 영역 오른쪽 위(모바일·태블릿은 지금처럼 헤더 오른쪽 위). 리포트(막대 차트) 아이콘을 앞에 더했다 | 메뉴 아래쪽은 눈에 잘 안 띄었다. 리포트가 기록 탭에서 따로 나오며 들어갈 길이 필요했다 |
| 6 | 운영 아이콘 | 막대 차트 | 방패 | 리포트 아이콘과 겹쳤다 |
| 7 | 워드마크 | 높이 24 | 사이드 메뉴 34, 모바일 헤더 30 | 로고가 작아 서비스 인상이 약했다 |
| 8 | 토스트 | 하단 가운데, 면접·결과 화면만 위쪽 | 모든 화면 하단 가운데. 아래가 답변 칸·버튼으로 막힌 화면은 그 바로 위 | 화면마다 위치가 달라 시선이 흩어졌다 |
| 9 | 목록 줄 hover | 줄 양옆 8px까지 `--hover` 회색 면 | 제목이 강조색, 줄이 오른쪽으로 3px, 끝 화살표가 3px 더. 키보드 포커스도 같다. 글자 크기는 그대로 | 회색 면이 덮개처럼 보였다 |
| 10 | 여우 | 랜딩·로그인·상태 화면에만 | 탭·하위 화면 오른쪽 아래에 떠 있는 피드백 버튼(누르면 피드백 화면). 처음 한 번 말풍선 "피드백 사항이 있으면 저에게 알려주세요."(8초 뒤 접힘, 닫으면 다시 먼저 뜨지 않음, hover·포커스에는 보임) | 메인 마스코트가 앱에서 보이지 않았고, 피드백을 바로 남길 곳이 필요했다 |
| 11 | 테마 토글 전환 | 아이콘이 바로 바뀜 | 해·달이 90° 돌며 엇갈려 바뀐다(0.5초), hover에 25° | 문서에 있던 전환이 구현에 빠져 있었다 |
| 12 | 오른쪽 위 도구 | 5번대로 리포트·테마 토글·알림(PC 내용 영역 오른쪽 위, 모바일·태블릿 헤더) | 테마 토글만(운영자의 모바일·태블릿 방패 아이콘은 그대로). 리포트는 PC 사이드 메뉴 "기록" 아래 항목(막대 차트, `/report`에서 켜진다), 모바일·태블릿은 MY 메뉴·홈 링크로 들어간다. 알림 아이콘은 뺐다 | 알림 아이콘은 MY로 가기만 해서 쓸모가 없었다. 리포트는 메뉴에서 바로 보이는 게 낫다 |
| 13 | 사이드 메뉴 MY 라벨 | "MY" | PC 사이드 메뉴는 "MY페이지"(화면 제목과 같게). 모바일·태블릿 탭바는 자리가 좁아 "MY" 그대로 | 화면 제목과 메뉴 이름이 달랐다 |
| 14 | 탭바(모바일·태블릿) | 유리(`--glass`, 거의 투명) | 시트 색 아래에 화면 바탕을 깐 불투명에 가까운 면(토스트와 같다, 블러가 안 되는 브라우저도 같다). 탭바 위 48px는 화면 바탕으로 흐려지는 페이드(고정, 누름을 막지 않는다). 탭바가 없는 하위 화면과 PC에는 페이드가 없다 | 뒤 글자가 다 비쳐 탭바가 눈에 안 띄었고, 글이 탭바에 닿을 때 아래 내용이 더 있다는 구분이 없었다 |

## 화면

### 앱 (모바일 390 기준)

흐름: **홈 → 면접(본 질문 → 꼬리질문 1·2·3) → 오늘의 결과**.

- **홈**: 워드마크 + 테마 토글(처음엔 알림 아이콘도 있었으나 뺐다, #114) / 날짜(고정폭) + 인사 / 오늘의 질문 유리 카드(3D Q, 질문 번호, 분야, 질문, 시작 버튼) / 3칸 통계(꼬리잇기·다시 나올 질문·약한 주제) / 떠 있는 유리 탭바(선택 탭은 안쪽 유리 캡슐).
- **면접**: 닫기 + 단계 점 4개(12×8, 현재 단계는 폭 32) + 단계 라벨(17px Bold 본문색) + 테마 토글 / 3D Q 면접관 + 상태 문구 / 질문 / 바텀 시트(답변 입력, "모르겠어요" 유리 알약 버튼, 글자 수, 원형 제출 버튼).
  - 제출 버튼은 30자 미만이면 비활성 모양, 넘으면 0.2초 동안 민트로 바뀐다.
  - 채점 중: 후광 맥박 + 점 3개.
  - 결과: 시트가 결과로 바뀐다. 점수 링 카운트업, 한 줄 평, 잘한 점, **보완할 개념 칩**, "꼬리질문 받기 · n/3". 칩은 질문마다 저장해 둔 핵심 키워드 중 답변에 빠진 것을 채점 결과에서 받는다(채점 출력에 키워드 칸을 더한다).
  - 꼬리질문 결과는 점수 대신 판정(잘 답했어요 / 조금 부족해요 / 틀렸어요 / 모르겠어요)과 한 줄 피드백이다. 처음엔 틀렸어요 없이 3단계였다 (2026-10-26에 더함). 판정 점 색은 잘 답했어요 `good`, 조금 부족해요 `mid`, 틀렸어요 `low`, 모르겠어요 `--dot-off`.
  - 잘한 점이 없으면(거의 빈 답, 틀린 답) 잘한 점 줄을 숨긴다.
  - 입력칸: 얇은 민트 스크롤바(4px), 맞춤법 검사 끔, 글자 16 이상.
- **MY**: 화면 제목은 "MY 페이지", 사이드 메뉴 라벨은 "MY페이지", 탭바 라벨은 자리가 좁아 "MY"(처음엔 사이드 메뉴도 "MY"였다, #114). 피드백 화면의 분류 칩은 공통 `.chip`의 radio 패턴(`role="radio"` + `aria-checked`). 운영 피드백 목록의 분류 배지 색은 바라는 기능 `--accent` · 버그 `--danger` · 신고 `--low` · 기타 `--sub`.
- **오늘의 결과**: 단계별 결과 목록(본 질문은 점수, 꼬리질문은 판정 점), 꼬리잇기·다음 복습 칸, 공유 버튼, 홈으로. C안 목업은 꼬리질문에도 점수를 매기고 평균을 보여줬으나, 복습 일정은 본 질문 점수로만 정하고 꼬리질문은 짧게 판정하는 채점 설계에 맞춰 판정 점으로 바꿨다.

### 랜딩 (PC 1440, 반응형)

순서: 스티키 헤더 → 히어로(소개 + 인터랙티브 채점 데모) → 주제 키워드 마퀴 2줄 → 대화 예시 → 기능 벤토 → 진행 방식 → 여우·꼬리잇기(잔디) → 체험(분야 선택) → 푸터.

- **헤더**: 화면 위에 붙어 따라오는 유리 헤더. 테마 토글이 여기 있다.
- **히어로 데모**: "채점해 보기"를 누르면 분석 연출(1.5초) → 점수 0→72 카운트업(1.4초) → 꼬리질문 카드가 천천히 떠오름 → "다시 보기". 영역 높이를 부드럽게 늘이고 줄여서 툭 끊기지 않게 한다.
- **마퀴**: 본문 폭 안에서만 흐르고 양 끝은 흐리게. 두 줄이 반대 방향, 마우스를 올리면 멈춘다.
- **벤토**: 4열(오늘의 질문 2×2, AI 채점, 꼬리질문 1×2, 다시 출제, 내 프로젝트 2×1, 기대 답안 2×1). 900px 이하 2열, 560px 이하 1열.
- 모바일 랜딩도 같은 섹션 순서를 한 열로 쌓는다.

### PC·태블릿 앱

| 너비 | 구조 |
|---|---|
| 모바일 (~767px) | 떠 있는 탭바 5개(불투명에 가까운 면 + 위쪽 페이드), 한 열 |
| 태블릿 (768~1023px) | 탭바, 내용 최대 너비 640 가운데 |
| PC (1024px~) | **왼쪽 사이드 메뉴**(홈·복습·기록·리포트·프로젝트·MY페이지). 세션·문서처럼 읽고 쓰는 화면은 내용 최대 720 가운데(넓은 화면은 45vw, 최대 920), 홈·기록·리포트처럼 훑어보는 화면은 2열 |

PC 뼈대 폭은 `app/globals.css`의 CSS 변수다. 화면 전용 레이아웃도 이 값을 쓴다. 처음엔 1024px 이상 모두 사이드 메뉴 224 · 내용 최대 992였는데, 27인치 풀 화면에서 가운데로 몰려 넓은 화면일수록 넓혔다(#114).

| 화면 폭 | 사이드 메뉴 `--nav-w` | 내용 시작 x `--shell-left` | 내용 최대 `--content-max` |
|---|---|---|---|
| 1024~1439 | 224 | 272 | 992 |
| 1440~1919 | 248 | 304 | 1200 |
| 1920~2399 | 264 | 328 | 1360 |
| 2400~ | 280 | 352 | 1520 |

- 사이드 메뉴는 화면 왼쪽 16에 떠 있고, 내용은 `--shell-left`부터 남은 폭의 가운데(좌우 최소 40)에 최대 `--content-max`다. 1440 이상에서 메뉴 항목은 높이 52·글자 17.
- PC 내용 영역 맨 위 오른쪽에 테마 토글(높이 44, 아래 8)이 있다. 리포트·운영 메뉴는 사이드 메뉴에 있다. 처음엔 리포트·알림 아이콘도 같이 있었는데, 리포트는 사이드 메뉴로 옮기고 알림(MY로 가기만 했다)은 뺐다(#114).

- 세션 화면은 PC에서 사이드 메뉴를 숨긴다.
- 기록은 PC에서 2열이다. 왼쪽 목록에서 행을 누르면 오른쪽에 요약이 뜨고, "기록 상세 보기"로 상세 화면에 간다. 제목·필터 띠는 위에 붙는 유리(sticky)이고, 필터·달은 칩이다. 처음엔 기본 select 드롭다운이었으나 다크에서 펼친 목록이 하얗게 떠 바꿨다(#117).
- 리포트는 기록 탭에서 빠져 별도 화면 `/report`다(MY·홈에서 진입, PC는 사이드 메뉴 "리포트"가 켜진다). 처음엔 모바일 헤더·PC 오른쪽 위 막대 차트 아이콘에서도 들어가고 탭은 "기록"이 켜졌는데(#117), 사이드 메뉴 항목으로 바꿨다(#114).
- 홈은 PC·태블릿에서 "복습할 질문"과 "최근 기록" 미리보기를 더한다. PC 홈은 가운데 열 : 오른쪽 열(통계 카드, "이번 주", "약한 주제")이 2:1 비율(오른쪽 최소 280)이고, 오른쪽 열은 스크롤해도 위에 붙어 있다. 처음엔 640+320 고정이었는데 27인치에서 가운데로 몰려 비율로 바꿨다(#115). 홈 인사의 닉네임 줄은 38px, 닉네임은 강조색(#115).
- 모달은 PC·태블릿에서 가운데 480 너비, 토스트는 모든 기기에서 하단 가운데(PC는 사이드 메뉴를 뺀 내용 영역의 가운데). 처음엔 PC만 오른쪽 아래였는데 시선이 흩어져 하단 가운데로 맞췄다(2026-10-27, #110). 면접·오늘의 결과처럼 아래가 답변 칸·버튼으로 막힌 화면은 그 바로 위 하단 가운데에 띄운다. 처음엔 이 화면들만 위쪽(헤더 아래)에 띄웠는데 위치가 화면마다 달라 바꿨다(#114).

### 3D Q 구현

Three.js(`@react-three/fiber`)로 여우 꼬리 Q 심볼(SVG)에 두께와 유리 재질을 준다. 처음엔 Spline으로 정했으나 무료 플랜은 로고가 붙고 빼려면 월 $12~15가 들어서 바꿨다(2026-10-23). 실시간 3D가 정지 이미지보다 못하면 **배경을 지운 정지 이미지 + 부유·반사 연출**로 간다. 정지 이미지는 512px 이상 투명 이미지로 만든다(원형 캡처를 그대로 쓰지 않는다).

## 모션

| 항목 | 값 |
|---|---|
| hover·선택 전환 | 0.2초 ease (위치, 배경, 그림자, 색) |
| 버튼 누름 | `scale(0.96)` |
| 카드 hover (랜딩) | 위로 4px + 강조색 테두리 링 |
| 버튼 화살표 hover | 오른쪽으로 4px |
| 화면 전환 | 새 화면이 아래 8px에서 올라오며 0.45초 페이드 |
| 테마 전환 | 배경·글자뿐 아니라 유리 면·배경 빛 색까지 0.5초. 토글 아이콘은 해·달이 90° 돌며 작아지고 커지며 엇갈려 바뀌고(0.5초), hover 시 25° 회전 |
| 3D Q | 부유 5~6초(위아래 10~14px, ±2~3°), 후광 숨쉬기 3.2초, 채점 중 맥박 1.8초. 이보다 빠르게 하지 않는다 |
| 점수 | 0에서 점수까지 18ms마다 2씩 카운트업(72점이면 약 0.65초), 링도 같이 차오름. 점수 링이 나오는 모든 화면(면접 결과·기록 상세·공유·체험 결과) |
| 바텀 시트 | 아래에서 0.5초 동안 올라온다 |
| 랜딩 첫 화면 | 배지 → 제목 → 설명 → 데모 → 버튼 차례로 0.08초 간격 등장 |
| 랜딩 스크롤 | 말풍선·벤토 칸·진행 숫자가 화면에 들어올 때 차례로 나타난다 (IntersectionObserver) |
| 배경 | 앱 기본 그라디언트는 움직이지 않는다. "빛 번짐"을 고르면 빛 덩어리가 천천히 떠돈다(14~16초). 랜딩은 자기 빛 덩어리가 스크롤의 0.12~0.32배로 따라 움직이고, 여우는 ±60px |
| 여우 피드백 버튼 | 아래에서 떠오르며 등장(0.5초), hover에 여우가 -8° 기울며 2px 위로, 말풍선은 0.25초 페이드 |

- **모션 줄이기**: 768px 이하에서는 스크롤 따라 움직이기를 끄고 배경을 느리게 한다. 기기의 "동작 줄이기"가 켜져 있으면 배경 움직임, 후광, 부유, 마퀴, 차례 등장, 화면 전환을 모두 끄고 점수는 바로 최종 값을 보여준다.
- Figma 화면은 멈춘 상태(점수는 최종 값)로 그렸다. 위 모션은 구현에서 넣는다.
- 스크롤 스냅은 쓰지 않는다(섹션 높이가 달라 끊긴다).
- CSS와 Framer Motion(무료)으로 만든다.

## 상호작용 상태

| 상태 | 모양 |
|---|---|
| hover (PC) | 버튼은 조금 밝게(`brightness(1.06)`). 랜딩 카드는 4px 떠오름 + 테두리 링. 글자 링크는 보조색 → 본문색 |
| 누름 | `scale(0.96)` |
| 포커스 (키보드) | 강조색 2px 바깥 테두리 |
| 비활성 (제출 버튼) | 옅은 유리 바탕 + 흐린 글자 |
| 선택 (체험 분야 칩) | 바탕과 글자를 반전 |

- hover는 마우스가 있는 기기(`@media (hover: hover)`)에서만 붙인다. 터치 뒤에 hover 모양이 남지 않게 하려는 것이다. 움직임(전환·누름 축소)은 "동작 줄이기"가 꺼져 있을 때만 켠다.
- 유리 버튼(원형 아이콘·보조 버튼·칩·알약)은 밝기만 올리면 거의 보이지 않아, hover 때 유리를 `--tab-active`만큼 진하게 한다.
- 카드 안 목록 줄(홈·복습·기록·프로젝트·MY 설정, 기록 상세의 접힌 칸)은 hover·키보드 포커스에 제목(색을 물려받는 글자)이 `--accent`가 되고 줄이 오른쪽으로 3px, 줄의 마지막 자식 화살표(svg)는 3px 더 나간다. 메타 글자처럼 색을 따로 지정한 글자는 그대로, 글자 크기도 그대로다. 공통 클래스는 `.hover-row`. 처음엔 줄 양옆 8px까지 `--hover` 면을 깔았는데 회색 덮개처럼 보여 바꿨다(#114).
- 탭바·사이드 메뉴의 선택 안 된 항목은 hover·키보드 포커스에 `--hover` 면 + 보조색 → 본문색. 선택된 항목은 그대로 둔다.
- 처음엔 hover가 버튼 밝기뿐이라 사이드 메뉴·목록 줄에서 구분감이 없어, 위 규칙을 더했다 (2026-10-27).

### 버튼 규칙

처음엔 보조 행동을 글자형 버튼으로 두었으나(C안 6번), 버튼감이 섞여서 2026-10-26에 모든 행동을 버튼 모양으로 통일했다.

- 주 버튼은 화면마다 하나(랜딩만 4개 예외), 알약형, 꽉 찬 민트. 하단 고정은 높이 56·모서리 28·16 Bold, 모달·카드 안은 48·24·15 Bold.
- 보조 버튼은 유리 버튼에 `--text` Bold 글자. 같은 묶음의 주 버튼과 높이·모서리·글자 크기를 같게 한다. 되돌릴 수 없는 행동(삭제·탈퇴)은 같은 모양에 `--danger` 글자.
- 배치: 모달은 가로 2개 같은 폭(높이 48, 간격 8, 순서 [취소] [주]). 하단 묶음은 세로로 주 버튼 + 보조 버튼(각 56, 간격 10). 나란한 두 행동은 같은 폭 2개.
- 헤더의 작은 동작("저장"·"편집" 등)은 유리 칩 버튼(높이 36, 13 Bold).
- 탭바·사이드 메뉴·목록 줄·"전체 보기" 링크·원형 아이콘 버튼·필터 칩은 그대로 둔다.
- 필터·선택 칩의 선택 상태는 `--tab-active` 바탕 + 1.5px 강조색 안쪽 테두리 + 강조색 Bold 글자(민트로 꽉 채우지 않는다).
- 소셜 로그인 버튼은 각 서비스의 대표 아이콘과 색을 쓴다. 카카오는 노란 바탕(`#FEE500`)에 검은 글씨, Google은 흰 바탕에 회색 테두리와 색깔 G, GitHub는 검은 바탕(`#24292F`)에 흰 글씨. 브랜드 색이라 테마가 바뀌어도 그대로다.

## 접근성

- 아이콘 버튼에 `aria-label`. 테마 토글은 지금 상태가 아니라 "바꿀 모드"를 읽어준다.
